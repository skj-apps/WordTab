## 3. TRAPS — things that will look like good ideas and are not

**`SRCCOPY` alone is not enough for the chrome blit. It MUST be `SRCCOPY | CAPTUREBLT`.**
The plain version produced a **byte-identical palette on a static ribbon**, both themes, every
derived colour - and then failed `check-look`'s live theme change **12 of 48**, because a plain blit
off the screen DC may come from a cached surface. Per-pixel `GetPixel` was *accidentally* immune
because it forces a readback every call. **A static A/B cannot see a stale cache**; only the test
that changes the input while the add-in runs can. If anyone "tidies up" that flag, this comes back
and looks like a palette bug.

**Do not gate the unfinished-frame guard on visibility.** `TryBind`'s predicate is the **absent
title**, with off-screen only as a second conjunct. Measured: *every* frame on this rig attaches
`visible=0`, good ones included, so a visibility-only guard defers every bind there is. `"Word"` is
deliberately NOT in the predicate - that is the Start screen, the last-document-closed window, and
Protected View for its first 31ms.

**Do not re-derive OnePage's illness test outside `WordTabOnePageView`.** The real test is
`columns > 1 && columns < 99`, because **99 is Word's "as many as fit" and IS healthy** - confirmed
in the field this session, 43 healthy joins logging `left alone at 99 page(s) across`. Three separate
attempts have now dropped the `< 99`.

**Do not key an item 1 guard on `!g_inModalLoop`.** `frames.cpp` already records that Win+Left and
Win+Right snap without the modal loop and without a system command.

**Do not run file-touching subagents against this working tree.** One rewrote `strip.cpp`,
`frames.cpp` and `wordtab.h` mid-session and silently deleted two edits that had already compiled,
despite "do NOT edit any file" in its prompt. Caught only because the build broke. See
`[[subagents-must-not-share-the-working-tree]]`.
